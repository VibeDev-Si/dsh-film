# 工作台技能进主会话；设置精简（2026-10-10）

## 工作台的技能怎么在主会话里用

工作台自带两个技能，原来是给它的内置 agent 用的：

- `workflow`：把创意、小说或剧本做成文本、图片资产和视频片段（主文件 94KB + 8 篇参考资料，含 Seedance 分段提示词规范）；
- `canvas`：画布操作手册（节点、连线、节点函数、排版）。

内置 agent 删掉以后，主会话的 agent 原本不知道它们的存在。现在插件把它们注册进 DSH 的技能目录（`ctx.skills.registerProvider`，与 DSH 自带的 Office 技能是同一种方式）：

| 技能 | 用途 |
| --- | --- |
| `vibedev-film` | 入口：什么时候用，先 `film_studio_open`，再用 `film_tools` / `film_call` 操作，详细方法见下面两个 |
| `film-workflow` | 工作台的 `workflow` |
| `film-canvas` | 工作台的 `canvas` |
| `film-<名字>` | 用户在工作台里自建的技能（数据目录 `skills/`），改动后不用重启就会出现 |

使用方式：

- **不用任何语法**：用户说"把这本小说做成短剧"，模型按技能描述自己选用；
- **显式调用**：输入框里键入 `/`，从建议里选，或直接输入 `/vibedev-film`、`/film-workflow`（DSH 原生的技能调用方式）；
- 不用 `@`：DSH 的 `@` 用于引用文件和会话。工作台的节点和工具插件不需要单独 @，agent 通过 `film_tools` 能看到全部操作。

每个技能正文前加了一段说明：文中提到的工作台工具（addNode、generateVideo…）都通过 `film_call` 调用；文件读写和提问用 VibeDev 自己的；`references/…` 在哪个目录。技能目录作为资源目录登记，agent 可以用自己的文件工具读参考资料。

## 设置只保留：界面设置、常规配置、FFmpeg

| 去掉的 | 原因 |
| --- | --- |
| 文本模型（原来显示账号托管说明） | 模型由 VibeDev 账号插件管理 |
| 插件市场（发现插件、已安装、每个插件的 GitHub 链接、本地安装、"获取 API Key"外链） | 用 VibeDev 自己的插件市场；节点与工具随影视工作台插件内置，且没有必填配置 |
| 隐私 | 影视模式下本来就不采集 |
| 关于（版本更新、仓库链接、交流群二维码、商务二维码、赞助商，打开时还会请求 ToonFlow 的赞助商接口） | 版本随插件更新 |

- **FFmpeg** 移到原"插件市场"的位置（本地成片与剪辑需要它）。
- **默认打开方式**：设置页随插件市场去掉。为了不留下改不回来的默认值，影视模式下"打开方式…"对话框不再显示"对此类文件设为默认"（原来默认是勾上的），也不保存默认值：普通文件用 VibeDev 的预览打开，"打开方式…"每次都让用户选。
- 更新检查只在 ToonFlow 桌面客户端里运行，影视模式下本来就不执行。
