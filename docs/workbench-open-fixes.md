# 打开工作台：白屏 / 不直接进画布 / 一闪一闪 / 偶发"运行产物不完整"（2026-10-10）

用户报告四件事，逐个查到根因并修复。全部有实测证据，不是推测。

## 1. 白屏（先显示"正在启动影视工作台…"然后白屏）

**根因**：安装目录里的 `apps/toonflow/build/web/index.html` 是**坏文件**——它指向的入口 `assets/index-B5wGWwAF.js` 已不存在（磁盘上是 `index-BjDhqBzZ.js`），它的修改时间还停在 **1985 年**。入口 JS 404 就是白屏。这是"就地镜像刷新安装目录"被写坏留下的残迹。

**修复**：

- `scripts/install-app.mjs`：**原子安装**。先在 `<安装目录>.new-<时间>` 里放好新产物，校验完整后，把旧目录改名备份、新目录改名就位、再删旧目录。两次 rename，宿主永远不会读到写了一半的产物。
- `scripts/verify-package.mjs`：新增**入口资源预检**——解析 `index.html` 里所有 `./…` 引用，逐个确认文件存在（现在 58 个引用全部核对）。这条检查当场就能抓住这次的白屏。
- 已对安装目录执行原子安装并核对：入口 `index-BjDhqBzZ.js` 存在、时间戳正常、无残留 staging 目录。

## 2. 不直接进画布（落到了首页/项目列表）

**根因**：侧栏打开时 `POST /api/dsh-film-studio/open` **不带 body**，宿主侧只从 body 读目录 → 拿不到目录 → 工作台按"没有项目"打开首页。只有 agent 显式调用 `film_studio_open` 时才会带目录。

**修复**：插件宿主半在请求没有指明目录时，从**当前会话的工作目录**取（`ctx.get('agents').currentInitiator().session.header.cwd`），于是点开标签页直接落在本会话的项目里。

## 3. 一闪一闪 + 打开慢

**根因**：客户端在标签页卸载 2.5 秒后**关掉工作台进程**（`/close`）。标签页被宿主渲染器反复挂载/卸载，于是反复"杀进程 → 重启（实测 1.1–1.5 秒）→ 整页重载"，这就是闪和慢。

**修复**（客户端 `TabBody`）：

- 不再关闭服务：进程伴随宿主会话存活，插件卸载时才停。重开就是复用已就绪的服务。
- 记住上一次可用的链接（模块级 `lastLink`），重挂载**立刻**渲染画布帧，后台再刷新链接；链接没变就不重设 `src`，因此不会整页重载。
- 刷新失败时**不再清空**：画面留在屏幕上，只在顶部加一条提示和"重试"按钮，所以一次失败不会变成白屏。

## 4. 偶发"Film 运行产物不完整（缺少 …index.html）"

**根因**：与第 1 条同源——就地刷新期间的半成品/坏文件。

**修复**：同第 1 条的原子安装 + 预检。另外查清了交付链路：宿主通过符号链接 `~/.vibedev-app/profiles/desktop/node_modules/dsh-film-studio` → `C:\vdp-wt\dsh-film-studio-install` 加载插件，所以**安装目录就是交付物**，原子安装正是对症的解法。

## 5. 新增：不往别人的目录里写字

直接进画布用"会话目录"，而会话目录经常是用户正在用的项目目录（例如桌面上的资料目录）。原实现会往里写 `.vibedev-film.json` 与 `画布1.json`。

**修复**：分两种触发方式。

| 触发 | 行为 |
| --- | --- |
| 自动打开（侧栏标签，会话目录） | 只在**空目录 / 我们自己的目录**里播种；陌生非空目录**一个文件都不写**，只当作项目打开，界面一行提示 |
| 显式指派（`film_studio_open` 带目录，链接带 `film=` + `project=true`） | 按既有规则创建/补建（不覆盖同名但不是我们的文件） |

# 第二轮（同日）：上一轮第 2、3、5 条的做法被推翻，按下面为准

## 上一轮没做到 / 做错的

- **第 2 条没生效**：`agents.currentInitiator()` 只在对话回合里有值，标签页发的是普通 HTTP 请求，取不到 → 仍然落在首页。
  **现在**：标签页组件自己读会话工作区（`useSessions(s => s.byId[sessionId]?.cwd)`，与宿主"文件"侧栏同一取法），放进请求体。
- **第 5 条与需求相反**：用户要的是"在当前工作区里兼容创建"，不是"不写"。而且画布页打开任何没有画布的项目时本来就会自建 `画布1.json`，"一个文件都不写"并不成立。
  **现在**：项目放在工作区下的 `VibeDev Film` 文件夹里，规则见 [project-directory.md](project-directory.md)。
- **链接缓存 bug**：`runtime.open()` 把第一次的项目目录记在实例里，之后换会话拿到的还是旧目录。**现在**链接按每次调用生成。
- **第 3 条"服务常驻"被否决**（常驻多占内存）。**现在**：关掉标签页就停服务，重新打开播放渲染动画。

## 本轮新问题与根因

| 问题 | 根因（实测） | 修复 |
| --- | --- | --- |

## 生命周期（替代上一轮第 3 条）

- 标签页类型 `keepMounted`：隐藏、切会话、换停靠位置都不卸载，iframe 原样保留。
- 点 ×：iframe 用 `moveBefore` 原样挪进隐藏容器 → 让页面写盘（等 `flushed`，最多 4 秒）→ 销毁 → 释放租约；最后一个标签页释放后 3 秒停服务，期间重新打开会复用。
- 宿主无论怎样结束（正常退出、崩溃、强杀），工作台进程的 stdin 管道关闭，进程自行退出：**不留孤儿进程**。
- 不预热。

# 第三轮：打开工作台报 "Request failed with status code 404"

两个页面里的错误，服务端测试都看不到（它们直接调接口，不经过页面）。这次用真实浏览器复现并验证。

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 404 | 页面写的是 `` `${apiBase}api/workspaces/film/prepare` ``，而默认 axios 实例已把 `apiBase`（`/s/<令牌>/`）设为 baseURL，实际请求成了 `/s/<令牌>/s/<令牌>/api/…`；服务端剥掉第一段后找不到路由，返回没有 message 的 404。项目中心的列表请求同样如此（列表永远是 0 个） | `apiPath()` 只给相对路径，由 axios 拼一次 |
| 修掉 404 后仍落到项目中心（第一轮"不直接进画布"的真正根因） | 入口改写写在 `main.ts` 正文里，而 `import` 先执行：路由模块导入时就创建 hash history 并读了当时的空 hash，首次导航走 `/` → `/hello` → `/home` | 改写挪进 `lib/filmEntry.ts`，作为 `main.ts` 的第一个 import；只改写全新进入（无 hash）的地址 |
| 设备互联轮询每次 404/403 | 只在带 `filmHost` 时停轮询 | 路径会话页（`/s/<令牌>/`）一律不轮询 |

## 新增：真实浏览器检查 `npm run check:browser`

`scripts/browser-check.mjs`：用 DevTools 协议驱动无头 Edge/Chrome，按侧栏标签页的方式打开工作台，检查：

- 画布出现；工作区下建出 `VibeDev Film/画布1.json`；工作区根目录只多这一个文件夹，用户文件不变；
- 数据目录里的节点**全部**加载（"添加节点"不会是空的）；
- 项目中心出现；
- 两个页面都没有 4xx/5xx 请求、没有页面异常或控制台错误。

修复前：画布没出现、文件夹没建、节点 0 个，并抓到 `/s/<令牌>/s/<令牌>/api/workspaces/film/projects` 404。修复后全部通过，安装目录同样通过。以后每次交付前都跑。
