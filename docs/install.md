# 安装与本轮验收清单

本文件给**执行安装的人**用。当前是 0.1.0 未发布前的本地安装产物验收，不是正式发布流程。

## 0. 现在能验到哪一步（先看这个）

账号插件线上是 **0.2.7**，**没有** Film 用的 `vibedevGateway` 接口（该补丁等 US 网关就绪后随 **0.3.0** 发布）。所以本轮能验的是：

- ✅ 插件能装、侧栏有入口、点击能打开工作台、进程与数据落位正确、失败提示清晰、卸载干净。
- ⏳ **模型链路验不了**：点开会走到"请启用带 Film 接口的 VibeDev 账号插件（0.3.0 及以上）"，这是**预期现象**，不是缺陷。
- ⏳ 真实文本/图片/视频生成、余额与限流等失败路径，要等 0.3.0。

## 1. 产物

在本仓库执行：

```powershell
npm run build:client            # 客户端半边（若尚未构建）
node scripts/assemble-app.mjs <ToonFlow 目录>   # 需要已构建的 ToonFlow（bun run build && bun run build:nodes）
npm pack                        # 得到 dsh-film-studio-0.1.0.tgz（约 55.7 MB）
```

包内应有：`package.json`、`cordis.patch.yml`、`lib/`、`client/client.js`、`apps/toonflow/build/{server,web,tools,nodes,ext,providers,skills}`、`apps/toonflow/runtime/bun.exe`。

## 2. 安装

- **宿主插件管理**：用 `dsh-film-studio-0.1.0.tgz`（或指向该包的安装规格）安装并启用；若宿主不认本地 tarball，退回到把它解包到宿主的插件目录再启用。
- 安装后**重启宿主**（或按宿主的插件重载方式），让宿主侧与客户端半边都加载。
- 不需要配置源码路径；不需要用户自己安装 Bun。

## 4. 出问题时的排查点

0. **"启用失败：… failed to import"**：宿主可能用 pnpm `link:` 把目录链进 profile，此时插件没有自己的 `node_modules`，任何**裸模块导入**（如 `@deepseek-ai/dsh-tools`）都会让整个入口失败（`ERR_MODULE_NOT_FOUND`）。
   本插件已把宿主侧半边打成**自包含**的 `lib/index.js`（除 `node:*` 外全部内联），因此链接安装也能加载；如果仍报这个错，请确认 `lib/index.js` 有 400 KB 以上，而不是几十 KB 的多文件产物。
1. `~/.vibedev/film-studio/data/logs/session-*.log` —— 服务端自己的输出，启动失败会写在这里。
2. 工作台进程起不来时，界面上的错误信息已带**服务端最后 3 行（已脱敏）**；连续 4 次失败会进入 60 秒冷却并说明。
3. 检查产物是否完整：`apps/toonflow/build/server/film.js`、`apps/toonflow/build/web/index.html`、`apps/toonflow/runtime/bun.exe`；缺哪个，错误信息会直接点名。
4. 若界面一直是"正在启动"：多半是宿主页面**跨源内嵌被拦**（宿主 CSP 的 `frame-src`）——把宿主日志里的 CSP 报告发我，我改成经宿主通道转发。
5. 若两个窗口互抢：删掉数据目录里的 `session.lock`（确认没有工作台在跑之后）。

- 剪辑台 Pro、`videoComposer.tool.js` 等第三方节点包的来源与许可未确认，**未打包**。
- 启动、画布缩放拖拽、内存与生成期间响应的实测数据（阶段五）。
