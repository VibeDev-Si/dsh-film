按顺序执行，每项做完给出**改动点 + 验证证据**。A/B/C 类是标识改名的三档处理，C 类留到最后与用户逐步进行。

## 1. 能力驱动改造 + `film_write_prompt`
- 生成节点面板的模型选项来自网关目录：只列目录里真实存在的模式/时长/分辨率/参考槽位数量。
- 换模型或换模式 → 归一化（时长取最近可用值、分辨率回落、参考数超限提示），**不静默改用户参数**。
- 提交前硬校验（参考数量、时长、比例、分辨率、首尾帧完整性），规则与账号插件的 `checkReferenceDurations` 一致。
- 能力不可读（`unreadableModesVersion`）的模式：不展示、不允许提交。
- 新增 `film_write_prompt`（主会话工具）：按节点类型 + 连线参考 + 技能模板写提示词；节点输入框旁的"VibeDev 写"按钮复用同一实现。
- 文本模型走宿主 `llm`（`listProviders`/`listModels`/`stream`）；设置页删掉"需要 0.3.0"那句。
- 参考实现（老版 canvas）：`video-modes.ts`、`normalize-for-model.ts`、`generation-presets.ts`、`reference-refusal.ts`、`prompt-skills.ts`、`canvas-node-prompt-panel.tsx`。

## 2. 同源托管（方案 A）

- 客户端 iframe 指向同源代理地址；保留"在新窗口打开"作为备用通道。
- 参考实现（老版）：canvas 由 VibeDev daemon 在 `/canvas/` 下同源托管 + `dsh-host.ts` transport。

## 3. 隐藏内置 Agent
- 隐藏工作台内的 Agent 面板与其模型选择器、会话入口；**不删除代码**（节点执行链可能依赖），先保证可回退。
